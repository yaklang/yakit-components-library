# 图标维护流程与 CI 简化计划

## 目标

Figma 修改通过 PR 进入仓库。保存本次原稿，生成当前 SVG 和组件导出，再离线验证规则、功能和类型。检查不访问远端，不要求维持历史外观，不以历史系统或浏览器版本判断正确性。

本次只整理图标维护、检查和 CI，不改变公开组件 API、当前图形或旧导入路径，不自动提交、推送、发布。跨平台改造仅限图标包及根目录图标入口；UI 只做必要的调用和图标集成清理。

## 图标和测试

- 删除旧截图、旧图标对照、历史审核和专属工具，需要时用 Git 追溯。
- fixtures 仅保留蒙版、渐变、多色、描边、非法输入和组件使用等功能样本。
- 混合测试中的有效功能断言保留，改用当前来源或独立样本；移除历史批次数量和路径字符串限制。
- 本次原稿继续保留，验证允许的主题色、Outline 线宽和引用 ID 转换，不把生成器自己生成的结果当成唯一答案。
- Outline 纯填充可直接导入并标记固定填充，不猜测中心线；Solid 和 Colorful 保留各自规则。
- 删除浏览器二进制哈希、系统版本、机器架构及历史安装路径等相等断言。

## 命令

- `pnpm icons:import --input …`：导入本次来源。
- `pnpm icons:update`：生成或更新 SVG、导出和展示配置，会写文件。
- `pnpm icons:update --check`：仅检查是否漏生成，不写回来源或生产文件。
- `pnpm icons:check`：包含生成检查，再执行当前来源审计、功能测试和类型检查，不重复执行相同测试组。
- 构建独立执行；独立运行验证只检查没有 UI 源码时能否生成、构建和使用图标包。

脚本采用 Node.js 文件 API 和工具入口，兼容带空格路径和 Windows 命令启动方式，不依赖 macOS 或 Unix shell。同步更新维护文档、Skill 和 AGENTS.md。

## CI

| 场景                       | 行为                                  |
| -------------------------- | ------------------------------------- |
| PR 创建或更新              | 按改动模块检查                        |
| 合并或直接推送 main        | 不启动普通质量 CI，发布工作流保留     |
| pre/\*\* 推送              | 保留原有触发                          |
| 只改普通文档               | 轻量检查                              |
| 图标素材或来源             | 当前全量图标、构建、UI 展示与消费验证 |
| 图标共用渲染或转换代码     | 再检查完整 UI 功能                    |
| UI 或 Storybook            | UI 检查，不重复图标专属测试           |
| 发布工具或相关配置         | 发布工具测试与打包验证                |
| 公共依赖或无法判断影响范围 | 全量相关检查                          |

图标构建产物在普通 CI 任务间复用；独立运行验证只在依赖、构建或包边界变化时执行。普通 SVG 更新不跑完整 Storybook 构建，也不重复三个平台的测试。

Linux 执行主检查；相关脚本、测试或构建配置变化时额外执行 Windows、macOS 检查，覆盖导入、生成、校验、功能和构建。PR 从共同基点比较，推送比较前后提交，新增、删除、改名均计入；无法比较则全量检查。保留 quality 汇总任务，失败或取消不能被忽略。

发布仍检查实际待发布产物，保留权限、版本、完整性和安装兼容检查；只移除其中过时和内部重复的图标检查。正常代码通过 PR 合并，本次不修改远端分支保护设置。

## 验收

1. 正确同步可以通过，不用更新旧截图；破坏当前规则、路径、引用、来源或导出会失败。
2. 忘记生成会明确提示；纯填充 Outline 可正常导入。
3. 当前图标源码与公开 API 不因整理而变化。
4. 普通 CI 不再由 main 推送触发，发布触发仍保留。
5. 分流、汇总和三个平台任务配置有自动检查；本机未实际运行的平台必须如实说明，不能称为已通过。
6. 构建和真实组件消费可用，没有活跃代码引用被删除的历史资料。
7. 记录检查调用的减少，不承诺未经可比 CI 记录验证的耗时提升。

## 执行结果（2026-11-12）

计划中的代码、CI 和文档调整已完成，尚未提交或推送。

减少的重复工作：

| 检查                   | 调整前                            | 调整后                                             |
| ---------------------- | --------------------------------- | -------------------------------------------------- |
| 图标导入与生成流程测试 | 主任务和独立运行任务各跑一次      | 统一入口跑一次                                     |
| 图标类型检查           | UI 入口和独立运行任务各跑一次     | 图标统一入口跑一次                                 |
| 历史基线检查           | 主任务和独立运行任务各跑一次      | 删除                                               |
| 图标构建               | 主任务、独立运行、UI 构建分别执行 | 普通 CI 构建一次并复用；涉及包边界时额外做独立构建 |
| 图标功能测试           | 多个命令组合，部分浏览器测试重复  | Node 测试组、浏览器测试组各跑一次                  |

本机 macOS 已通过：

- `pnpm icons:check`：30 项流程测试、824 项 Node 测试、82 项浏览器测试、6 项仓库图标测试，以及来源审计和类型检查。
- 图标构建、包验证和不依赖 UI 源码的独立运行验证。
- UI 的 102 项组件测试、13 项图标展示集成测试、48 项公开包约定测试、9 项构建产物消费测试，以及类型检查。
- 图标和 UI 的 lint（无错误，仍有警告）、3 项自动导入测试、264 项发布工具测试、8 项 CI 分流和汇总测试。
- UI 与 Storybook 构建、包验证和打包试运行。
- 两份工作流的 YAML 解析及 Git 差异检查。

逐文件核对了 1,703 个图标源码文件，内容哈希均未变化；四类图标保存的原稿也未变化。

Windows、Linux 已配置 CI 检查，本次没有远端执行结果，不能视为已通过。增加了图标文件与两个图标展示生成文件的 LF 换行约定，避免 Windows 自动换行造成哈希或生成差异；这属于文件格式约定，不锁定系统或辅助工具版本。

当时发现一项既有的 UI 发布限制：总压缩包上限为 4,930,040 字节，实测为 5,882,308 字节。用修改前的 Storybook 和包配置、同一套依赖及未改动的库源码产物做对照，结果为 5,902,416 字节，也超过上限。

2026-11-13 经用户确认，取消 UI 总包压缩大小、解压大小和文件数量的硬性上限，清理普通 CI、发布工作流和本地发布试运行中的调用，以及专用脚本和基线配置。UI 包包含 Storybook 展示站，整体体积不等于业务页面加载的组件体积。保留功能、类型、构建、包内容和安装使用检查；图标包独立的体积规则继续保留。
